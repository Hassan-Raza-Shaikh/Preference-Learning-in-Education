Preference Learning in Education · Study Report

Format Over Correctness

Teaching small language models to solve systems of equations by a specified method — and what a fully verified, sympy-graded pipeline reveals about training data, format, and preference tuning.

Source CAHLR/OATutor-Content Models Qwen2.5-1.5B (general · math) Grading sympy exact-answer Hallucinated math 0

The question. When a small LLM is trained to solve a linear system by a named method (substitution, elimination, Cramer's rule, …), what actually moves the needle — the base model's prior, the format of the solution targets, or the training stage (SFT vs. DPO)? And does simply adding more verified data help?

The short answer. For 1.5B models, how a correct solution is written matters more than the fact that it is correct: worked targets that show the arithmetic beat terse ones at every turn. SFT beats DPO decisively. And naive data scaling did not help — distribution and training budget matter more than volume. Every number below is graded exactly by a symbolic checker; every training target was independently re-verified.

01

Headline findings

+8pt

Format beats correctness of the target

Switching terse solutions for worked ones (same math, arithmetic shown) lifted SFT accuracy for both models — general 0.087 → 0.159, math 0.214 → 0.286 — the single largest controllable lever in the study.

SFT ≫ DPO

Preference tuning hurt at this scale

Every DPO run scored below its own SFT starting point, collapsing the general model to near-zero — despite preference pairs a rule-based judge separates perfectly. A capacity boundary, not a data flaw.

7× ⇏

More data did not mean better

Growing the training set 7× with verified synthetic systems left the math model flat and the general model worse. Data distribution and training budget dominated raw volume.

03

Building verified targets

Questions are taken verbatim from OATutor; only solutions are generated — by sympy, not by a language model — so no fabricated arithmetic can enter the data. For each system we produce a solution by every applicable method and verify each one by substituting the answer back into the original equations.

04

Experimental setup

  • Split by system — 164 → 114 train / 24 valid / 26 test (126 method-solutions), no leakage, identical across every condition.
  • Two matched bases — Qwen2.5-1.5B-Instruct (general) and Qwen2.5-Math-1.5B-Instruct (math), both 4-bit, run on Apple Silicon via MLX.
  • Training — LoRA (8 layers) with mlx-lm-lora; SFT then DPO (β = 0.1).
  • Metric — exact answer accuracy on held-out systems, graded by sympy. Method-faithfulness and error modes logged alongside.

Why this is clean: a symbolic grader means there is no LLM-judge noise, and the two bases start at nearly the same overall accuracy (0.389 vs 0.381), so differences in how they respond to training are attributable to the pretraining prior — not the starting point.

08

Scaling verified data — and a correction

Adding 5,624 verified synthetic solutions (7× the real set → 6,189 SFT examples, 0 contamination with the test set) did not help.

ModelBaseWorked SFT
(114 sys)		Scaled SFT
(6,189 ex)
general0.3890.1590.095
math0.3810.2860.270
 Math flat (within noise); general regressed.

A correction we made openly. The first hypothesis — “synthetic is harder” — was refuted by inspection: synthetic systems have similar coefficient sizes (5.4 vs 6.0) but 0% fractional solutions vs 37% in real data, and the scaled run used more iterations (1500 vs 600). So the general model's drop conflates a distribution mismatch with a training-budget confound. The honest reading: for small models, data distribution and training budget matter more than raw volume.

09

Limitations & next steps

  • Small 1.5B / 4-bit models on a laptop — the “training net-hurts a capable base” effect should shrink at 7B+ with more headroom.
  • 114 real training systems is tiny; the clean scaling test is a compute-matched control (worked-114 at 1500 iters) to isolate volume from steps.
  • The substantive fix the analysis points to: a distribution-matched synthetic set — ~37% fractional solutions, matched coefficient statistics — then re-scale.
  • DPO harmful here; worth revisiting with KL regularization, on-policy refresh, or harder multi-step negatives.
  • Method-faithfulness (does it use the requested method) is logged and is a promising primary metric where even the strong base has headroom.
